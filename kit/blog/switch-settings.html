The short version

Listing every setting of n on/off switches in increasing binary order is the same as counting from 0 to 2ⁿ − 1 and writing each number in binary with exactly n digits.

You need four ideas for that: why there are 2ⁿ settings, how binary place values work, how to read one bit out of a number (v >> pos & 1), and why the answer costs O(N · 2ᴺ) however clever the code is.

1The problem

Exercise 1.1.16 in the DSA track asks for switch_settings(n): every way to set n on/off switches, written as strings of '0' (off) and '1' (on), in increasing binary order. You build the strings yourself rather than with a formatting helper.

switch_settings(2)    # ['00', '01', '10', '11']
switch_settings(3)    # ['000', '001', '010', '011', '100', '101', '110', '111']
switch_settings(0)    # ['']: no switches still leaves one setting, the empty one

Working on it now? Keep the exercise open in the workbook (it's the same in Java and Go). This post teaches the ideas. Complete solutions are folded under Show code, so you choose when to look.

2Why there are 2ⁿ settings

Each switch is on or off, whatever the others are doing. One switch gives 2 settings. Add a second and every one of those 2 settings appears twice, once with the new switch off and once with it on: 4. A third doubles it again: 8. With n switches you multiply 2 by itself n times, so there are 2 × 2 × … × 2 = 2ⁿ settings.

A tree shows it best. Each level decides one switch, trying 0 (off) before 1 (on), and each path from the root to a leaf is one complete setting.

Decide one switch at a timePick a leaf to light up its path. Each level doubles the number of branches.

Read the leaves from top to bottom: 000, 001, 010, 011, 100 and so on. The tree hands you the settings already in increasing order, for two reasons. It always tries 0 before 1, and it decides the leftmost switch first, and the leftmost switch is the one worth the most. The next section explains why.

3Binary place values

In decimal, the digits of 345 are worth 100, 10 and 1, each place ten times the one to its right. Binary works the same way with two instead of ten: from the right, the places are worth 1, 2, 4, 8, 16 and so on, which is 2⁰, 2¹, 2² and up. A setting is a number. Add up the places whose switch is on:

#  8  4  2  1      place values
#  1  0  1  1      the setting '1011'
#  8 +0 +2 +1  ==  11

With n switches the smallest value is all off (0) and the largest is all on, 2ⁿ − 1 (for 4 switches, 1111 = 15 = 16 − 1). Every whole number in between appears exactly once. So "every setting in increasing binary order" just means counting from 0 to 2ⁿ − 1. Try it: toggle the switches, or count up one at a time.

A row of switches is a numberTap a switch to flip it. +1 shows the carry: trailing 1s turn to 0 and the next 0 turns to 1.

Counting past the top wraps back to all off: (v + 1) % 2**n. That's the same wrap-around as in the post on Python's %.

One detail matters for the exercise. As a plain number, 3 in binary is 11. As a setting of 4 switches it's 0011: the switches that are off on the left still count. Every string you return has exactly n characters.

4Reading one bit out of a number

Number the positions from the right, starting at 0, so position pos is worth 2pos. There are two ways to ask whether the switch at pos is on in the number v.

With division

Divide away the lower positions, then look at the last binary digit: v // 2**pos % 2. For 13 (1101) and position 2: 13 // 4 is 3 (11), and 3 % 2 is 1, so the switch is on. Calling divmod(v, 2) over and over peels off the bits from the right, one per call.

With a shift and a mask

Two operators do the same job directly on the bits:

  • v >> pos shifts the bits right by pos places, and the lowest pos bits fall off the end. For non-negative v it equals v // 2**pos.
  • x & 1 keeps only the last bit, so it equals x % 2. The 1 is a mask: a number with a 1 only in the place you want to see.
v = 13           # 1101
v >> 2           # 3   (11): the two lowest bits fell off
v >> 2 & 1       # 1   bit 2 is on
v >> 1 & 1       # 0   bit 1 is off
v // 4 % 2       # 1   the same question, answered with division
1 << 4           # 16  a 1 shifted left 4 places: 2 ** 4

In Python >> binds tighter than &, so v >> pos & 1 means (v >> pos) & 1, and comparisons come after both, so v >> pos & 1 == 1 works too. Java is different: there == binds tighter than &, so you must write (v >> pos & 1) == 1. In Go, >> and & share a precedence level and group left to right, so v>>pos&1 is fine. In Java and Go, 1 << n overflows once n reaches the width of the integer type (31 for a Java int), but by then the list wouldn't fit in memory anyway.

5Writing the bits left to right

A string reads from the most valuable switch to the least, so you need positions n − 1 down to 0:

range(n - 1, -1, -1)    # n - 1, n - 2, ..., 1, 0: the stop is excluded, so it's -1
reversed(range(n))      # the same positions, easier to read

Collect the characters in a list and join them once at the end with "".join(chars). Each setting costs n steps to write whichever way you do it. The habit matters more in other languages: Java has StringBuilder, and Go fills a []byte, where '0' + bit turns the bit into a character.

The slips that trip people up most:

  • Missing position 0. range(n - 1, 0, -1) stops before 0, so every string comes out one character short.
  • Losing the leading zeros. bin(3)[2:] is '11', not '0011'. Always write exactly n positions.
  • Bits in reverse. If you read bits from the right with divmod or from pos = 0 upwards, reverse them before joining, or 1 comes out as '1000'.
  • One setting short. range(2 ** n - 1) stops at 2ⁿ − 2 and misses all-on. range(2 ** n) is right.
  • Special-casing zero. There's no need: range(2 ** 0) is one value with no bits to write, which gives [''], exactly what the test expects.

6Three ways to list every setting

All three produce the same list in the same order. Try writing one yourself before you open the code.

Count, then convert each number

Loop v from 0 to 2ⁿ − 1 and write each one out with the bit reading from section 4. This is the approach the exercise's Big O line describes.

Show code 
def switch_settings(n):
    out = []
    for v in range(1 << n):                 # 0 .. 2**n - 1
        chars = []
        for pos in range(n - 1, -1, -1):    # most valuable switch first
            chars.append("1" if v >> pos & 1 else "0")
        out.append("".join(chars))
    return out

Grow the list by doubling

Take the list for n − 1 switches. Put a new switch in front: first '0' before every old setting, then '1' before every old setting. The order stays increasing, because everything starting with 0 is smaller than everything starting with 1. This is section 2's doubling, turned into code.

One more switch, twice as many settingsThe new switch goes in front: off for the top half, on for the bottom half.
Show code 
def switch_settings(n):
    out = [""]                      # 0 switches: one empty setting
    for _ in range(n):
        out = ["0" + s for s in out] + ["1" + s for s in out]
    return out

Decide switch by switch (recursion)

Walk the tree from section 2. At each level, choose 0 and go deeper, then come back and choose 1. When every switch is decided, record the setting. This shape, choose, recurse, undo, is the heart of the recursion and backtracking chapters.

Show code 
def switch_settings(n):
    out = []

    def choose(prefix):
        if len(prefix) == n:
            out.append(prefix)
            return
        choose(prefix + "0")    # off first, so the order stays increasing
        choose(prefix + "1")

    choose("")
    return out

Checking your answer

The standard library can produce the same list in one line. The exercise asks you to build the strings yourself, but the library is handy for testing your version against:

import itertools
expected = [format(v, f"0{n}b") for v in range(2 ** n)]                 # 'b' is binary, '0n' pads to n digits
expected = ["".join(p) for p in itertools.product("01", repeat=n)]    # the same list
assert switch_settings(n) == expected

7What it costs

There are 2ⁿ settings and each takes n characters to write, so the work and the output are both O(N · 2ᴺ). The exercise writes this as O(2ᴺ) with the N in brackets: the doubling is what dominates. No algorithm can beat it, because the answer itself is that long, and writing an answer takes at least as long as its length.

Exponential growth is easy to underestimate. Each extra switch doubles everything, so ten extra switches multiply it by 2¹⁰ = 1024. Slide to see:

How fast 2ⁿ growsTime and memory are rough estimates for the Python solution, measured on one laptop.

On that laptop, 20 switches (about a million settings) took 0.75 seconds and 72 MB. 22 switches took 3.2 seconds and about 300 MB. At 30 switches the list alone would need roughly 85 GB. That's why problems that try every on/off combination are only practical for small n, typically 20 to 25 at most.

8Where this comes back

A setting of n switches is also a subset of n items: switch i on means item i is chosen. Listing every setting lists every subset, which is how brute force over "every combination" works.

items = ["tea", "toast", "eggs"]
for s in switch_settings(len(items)):
    chosen = [x for x, bit in zip(items, s) if bit == "1"]
    # '000' -> [], '101' -> ['tea', 'eggs'], '111' -> all three

The same ideas run through later chapters. Backtracking builds subsets switch by switch and prunes branches that can't work. Bit vectors pack many on/off flags into one number and read them with the same >> and &. The compact sets chapter covers those.
