The short version

a % n is the remainder after dividing a by n. In Python the result always has the same sign as n. So with a positive n you always get a number from 0 to n − 1, even when a is negative.

That one property is why (i + k) % n rotates arrays and wraps indexes correctly in both directions. C, Java, Go and JavaScript give the remainder the sign of a instead, so their -7 % 3 is −1 where Python's is 2.

1What % computes

Divide 17 by 5: it goes in 3 times (that's 15) with 2 left over. 17 // 5 is the 3 and 17 % 5 is the 2. Python ties the two operators together with one rule that holds for every pair of integers, as long as n isn't 0:

a == (a // n) * n + (a % n)    # always True

17 // 5    # 3
17 % 5     # 2,  because 17 == 3 * 5 + 2

So a % n is just a - (a // n) * n: what's left after you take away as many whole ns as fit. For positive numbers that's the remainder you learned at school.

The surprises with negative numbers all come from one question: when a / n isn't a whole number, which way does // round? Python always rounds down, towards minus infinity, never towards zero. Keep that in mind; section 3 shows why it matters.

2Wrap-around: think of a clock

The number line goes on forever in both directions. % n folds it into a ring of n slots numbered 0 to n − 1. Start at slot 0 and walk a steps (forwards when a is positive, backwards when it's negative), and you stop on slot a % n. Because Python's answer always stays in 0 … n − 1, this works in both directions.

Three hours before midnight on a 12-hour clock is 9 o'clock, and -3 % 12 == 9. The number of laps doesn't matter; only the leftover steps decide where you stop. That's why step counts of 2, 14 and −10 all land on the same slot of a 12-slot ring, and it's the whole trick behind rotating arrays.

3Negative numbers: round down, not toward zero

Take -7 % 3. The exact quotient is −2.33…, and the two ways of rounding it give two different answers:

  • Python rounds down: -7 // 3 is −3. The multiple of 3 it takes away is 3 × −3 = −9, which sits below −7. What's left is −7 − (−9) = 2.
  • C, Java, Go and JavaScript round toward zero: the quotient is −2. The multiple is −6, which sits above −7, and what's left is −7 − (−6) = −1.

On the number line, Python steps back from a to the nearest multiple of n at or below it (for a positive n) and measures forward from there. A distance measured forward is never negative.

Rounding down vs rounding toward zeroThe shaded blocks are whole multiples of n. Each arrow runs from the chosen multiple to a, and its length is the remainder.

Line up i % 3 for a run of i values and the difference jumps out. In Python the pattern 0, 1, 2 carries on straight through zero. With rounding toward zero it flips into a mirror image for negative i, and that mirror image is what breaks wrap-around code in those languages.

The rule of thumb: in Python the remainder takes the sign of the divisor n (or is 0). In the truncating languages it takes the sign of a. The two agree only when a and n have the same sign. You'll rarely divide by a negative number in practice. The case that bites is the second row, a negative a with a positive n, and that's exactly what you get from i - 1 at index 0 or from rotating left.

A few more facts

divmod(-7, 3)      # (-3, 2): the quotient and remainder in one call
-5.5 % 2           # 0.5: floats follow the same rule
math.fmod(-7, 3)   # -1.0: the round-toward-zero remainder, if you want it
7 % 0              # ZeroDivisionError

4Rotating an array

Rotating right by k moves every element k places to the right, and anything that falls off the end comes back in at the start. With a = ['A', 'B', 'C', 'D', 'E', 'F'] and k = 2 you get ['E', 'F', 'A', 'B', 'C', 'D'].

Where does the element at index i go? To i + k, folded back onto the array, which is (i + k) % n. That's the clock from section 2 with n slots.

def rotate_right(a, k):
    n = len(a)
    out = [None] * n
    for i, x in enumerate(a):
        out[(i + k) % n] = x     # where does a[i] go?
    return out

You can also ask the reverse question: which element lands at index j? The one that started at (j - k) % n, which gives the one-liner [a[(j - k) % n] for j in range(n)]. Here j - k is often negative, and Python's % still lands it inside the array.

% takes care of three awkward cases at once:

  • k bigger than n. Rotating 6 items by 8 is the same as rotating by 2, because 8 % 6 == 2. Each full lap puts every element back where it started.
  • Negative k. Rotating left by 2 is rotating right by −2, and (i - 2) % n stays between 0 and n − 1 because Python's % is never negative for a positive n.
  • k of 0 or a multiple of n. (i + 0) % n == i, so nothing moves.

The slicing version

def rotate_right(a, k):
    if not a:
        return []
    s = -k % len(a)         # index of the element that ends up first
    return a[s:] + a[:s]

rotate_right(list("ABCDEF"), 2)    # ['E', 'F', 'A', 'B', 'C', 'D']
rotate_right(list("ABCDEF"), -2)   # ['C', 'D', 'E', 'F', 'A', 'B']  (left by 2)
rotate_right(list("ABCDEF"), 8)    # same as k = 2

-k % n means (-k) % n, because unary minus binds tighter than %. For k = 2 and n = 6 that's 4, so the result is a[4:] + a[:4]. To rotate left by k, use s = k % n.

A common bug: the tempting a[-k:] + a[:-k] works while k stays between −n and n. Past that it quietly returns the list unchanged: for 6 items, a[-8:] is the whole list and a[:-8] is empty. The widget above marks it ✗ whenever that happens. Reduce k with % n first. And if you want this built in, collections.deque has rotate(k), which rotates right for a positive k, left for a negative one, and accepts any size.

5Everyday patterns

Once you see % as "fold onto a ring of n", it shows up all over interview problems and real code.

Step around a ring

nxt = (i + 1) % n
prv = (i - 1) % n    # at 0 this gives n - 1

Round-robin turns, circular buffers, the neighbours of the last seat at a round table.

in Java and Go, (i - 1) % n is −1 when i is 0. Write (i - 1 + n) % n there.

A rotated view, no copying

def at(a, start, i):
    return a[(start + i) % len(a)]

for i in range(2 * n):    # go round twice
    x = a[i % n]

Read the array as if it began at start. Circular-array problems often loop twice around like this.

Days of the week

DAYS = ["Mon", "Tue", "Wed", "Thu", "Fri", "Sat", "Sun"]
DAYS[(2 + 10) % 7]    # 10 days after Wed: 'Sat'
DAYS[(2 - 10) % 7]    # 10 days before Wed: 'Sun'

Going back in time is just a negative offset.

Even or odd

n % 2 == 1    # odd, negatives too, in Python
n % 2 != 0    # odd, in every language

-3 % 2 is 1 in Python but −1 in Java, Go, C and JavaScript, so n % 2 == 1 misses negative odd numbers there.

Split a quantity

minutes, seconds = divmod(125, 60)    # 2, 5
hours, minutes = divmod(minutes, 60)

divmod(-125, 60) is (-3, 55). That's correct floor arithmetic but a strange duration. Split abs(x) and put the sign back.

Digits of a number

n % 10     # last digit: 1234 -> 4
n // 10    # drop it:    1234 -> 123

-1234 % 10 is 6, not 4, because −1234 = 10 × −124 + 6. Work on abs(n).

Shift letters

def shift(c, k):
    return chr((ord(c) - ord("a") + k) % 26 + ord("a"))

shift("y", 3)     # 'b'
shift("b", -3)    # 'y': undoing is a negative k

The alphabet is a ring of 26. Python's % makes decoding free.

Hash buckets

bucket = hash(key) % num_buckets    # always 0 .. num_buckets - 1

hash() can be negative, and Python's % still lands in range.

in Java, h % m can be negative and Math.abs(h) % m breaks for Integer.MIN_VALUE. Use Math.floorMod(h, m).
